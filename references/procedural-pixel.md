# 纯代码像素渲染（procedural pixel）：一张图都不出

和 [pixel-narrative.md](pixel-narrative.md)、[stardew-pixel.md](stardew-pixel.md) 属于同一个像素家族，
但生产方式相反：那两份是「AI 出图 → 图生视频」，这一份**全片不出图**——
sprite 用字符网格和矩形画，场景用程序生成，每一帧由 Python 直接画出来。

代表案例：《简单爱》像素 RPG MV。4 分 31 秒、62 个场景、30fps、1024×576，
全片零张 AI 图、零次图生视频，其余工作全在代码里。

## 一、什么时候该走这条路

| | 代码渲染 | AI 出图 + 图生视频 |
|---|---|---|
| 单镜成本 | 0 | 1 张图 + 1 段视频 |
| 一致性 | 完全相同（同一个函数画 41 次） | 靠角色设计图 + 文字复述维持，仍会漂移 |
| 迭代 | 改一个数字重渲，几秒 | 重出一遍，分钟级且计费 |
| 时间控制 | 精确到帧，可为了一个字晚 80ms 重渲 | 只能整段调 |
| 适合 | 几何可描述：像素场景、UI 界面、文字卡、地图、HUD、数值 | 写实光影、手绘质感、微表情、复杂材质 |
| 不适合 | 需要「演技」和真实光照的镜头 | 需要上百次微调的镜头 |

判断只有一条：**这个画面能不能用「矩形、线、填充、位移」描述出来？**
能，走代码；不能，走 AI。也可以混：本项目的手绘特写（眼睛、后脑勺、脚、天台）
是逐像素画曲线的，那属于代码，因为曲线参数可调；而「一片有湿润感的草地」属于 AI。

**代价要提前说清**：省的是调用费，花的是开发时间。一个可复用的 sprite 库加场景函数
写下来是几千行，第一支片子最贵，第二支起几乎免费。只做一支，AI 路线更快；
要做第三支、或者要反复改到「每个字都卡准」，代码路线的总成本才会反超。

## 二、四层结构

```
project/
├── storyboard.json    # 唯一数据源：62 个场景的 start/end/kind/line/action...
├── art.py             # sprite 原语：人物、道具、云、树、长椅、自行车
├── world.py           # 世界长卷：2200px 横向场景 + 视差层 + 调色
├── render.py          # 逐帧渲染：场景类型分发 → 帧合成 → ffmpeg
├── sfx.py             # 音效合成：131 条，全部程序生成
├── sfx-cues.json      # 音效事件表（时间点 + 音色 + 参数）
├── check_sync.py      # 音画同步复核
└── output/
```

**数据源必须是 JSON，不能是代码。** 场景的时刻、镜头类型、台词、动作都在
`storyboard.json` 里；渲染器只做 `getattr(self, "st_" + sc["kind"])` 的分发。
这样调一个时间点不用碰 Python，改一次排版不用重跑 build 脚本。

## 三、逻辑画布与整数放大

全片在 **256×144** 的逻辑画布上画，最后整数倍 NEAREST 放大：

| 用途 | 逻辑画布 | 倍数 | 成片 |
|---|---|---|---|
| 本片（16:9，体积优先） | 256×144 | ×4 | 1024×576 |
| 需要 1080p 时 | 240×135 | ×8 | 1920×1080 |
| 竖版 9:16 | 108×192 | ×10 | 1080×1920 |

三条硬规矩：

- **所有坐标必须是整数**。`int()` 不能省。小数坐标经 NEAREST 放大后会出现 1px 的缝和毛边，
  而且只在某些帧出现，最难查。
- **倍数只能整数**。×4.5 会让像素格变成非等宽，观感立刻从「像素画」掉成「低清图」。
- **不要先画大再缩小**。`Image.resize(..., LANCZOS)` 缩小会把像素边糊掉，那是反像素。

放大函数就一行，别写复杂：

```python
def up(img, scale=4):
    return img.resize((img.width * scale, img.height * scale), Image.Resampling.NEAREST)
```

## 四、帧的合成顺序（最容易做错的一层）

帧不是「画完场景就结束」。本项目 `frame(t)` 的顺序是这样的，
**每一层的先后都有理由，调换任何两层都会出可见的错**：

1. **画场景**（256×144 逻辑画布；文字类场景直接在 1024×576 上画）
2. **调色** `world.grade(img, tod)` —— 晨/午/昏/夜整体换色，只对像素场景做
3. **整数放大** `up(img)` —— 从这里开始都是 1024×576 空间
4. **HUD 顶栏** —— 不参与放大，始终清晰
5. **字幕** —— 在 HUD 之后、UI 之前
6. **交互层** `ui()` —— 必须压在字幕**之上**，它模拟的是「玩家正在操作」的那一层
7. **遮幅压条** —— 底部 3 格压暗，让人以为字幕区在画面外
8. **扫描线** —— 贴一层极淡的横线，统一质感
9. **淡入淡出** —— 最后一层黑，连 HUD 一起盖掉

两个反直觉的点：

- **HUD 和字幕不能进放大**。它们要在 1024×576 上直接画，否则中文字会被 NEAREST 放大成方块。
  这就是为什么 `FULL_KINDS`（title / card / glyph / ending / credits / black / map）要单独走一条路：
  它们连底图都是全分辨率画的。
- **交互层的落点必须避开字幕框和顶栏**。本项目约定 UI 元素不进入 `y<52`（顶栏）
  和 `y>468`（字幕框）。先定这两条边界，再设计按钮位置——反过来做一定会挡字。

## 五、文字：两条路线，选定一条，别混着用

### 路线 A：像素字（风景和字都是像素）

只有在你**真的能给出足够大的字号**时才成立。实测中文字高的物理下限：

| 字高 | 结果 |
|---|---|
| ≤14px | 笔画开始粘连，「杰」的四点并成一条、「爱」的中宫糊成一块 |
| 15–20px | 可辨但吃力，需要描边 |
| ≥32px | 稳定可用 |

配套三条：

- **蒙版必须二值化**。抗锯齿会在字缘留一圈灰，NEAREST 放大 8 倍后变成半透明色晕，
  描边色从字缝里透出来，小字直接糊成一团墨。
  `m = m.point(lambda v: 255 if v >= 128 else 0)`
- **小字不要投影**。8px 一格的字加投影，等于沿字底拉一条 8px 的暗边。
- **缩小字距来救字宽是错的**。宁可减字号、减笔画密的字，也别压字距。

### 路线 B：风景是像素的，字不是（推荐）

底图走逻辑画布 + 整数放大；**题字在成图的原生分辨率上直接排**，保留抗锯齿，
只加高斯模糊投影。观众看到的是「像素风的画面配一张正经的字」，
这比「像素字体」在所有尺寸下都更耐看，也更符合 MV 的调性。

```python
# 投影用高斯模糊，不用描边。亮而软的天空上，硬描边像贴纸。
sh = Image.new("L", size, 0); sh.paste(mask, (0, dy))
sh = sh.filter(ImageFilter.GaussianBlur(radius))
out = _stamp(out, sh, color, alpha)      # 先投影
out = _stamp(out, mask, fill, 255)       # 后字面
```

### 封面不要从成片抽帧

成片的每个镜头是为「看完」设计的，封面只要在 **320×180 的缩略图**里站住一秒。
所以封面是独立渲染路径（`cover.py`）：同一套 `build()` 场景函数，换参数（地平线高度、
水面高度、太阳位置、长椅位置），换画幅，重排题字。抽帧出来的封面在缩略图里永远糊。

验收方式就一条：**缩到 320×180，看歌名还认不认得出，歌手名还辨不辨得出三个字。**

## 六、五个必踩的坑

### 1. RGBA 半透明：`ImageDraw.Draw(img, "RGBA")` 不混合，它替换

在 RGBA 图上拿 `"RGBA"` 模式画半透明，填 `(255,182,116,9)` 得到的不是 9/255 的淡橘色，
而是「一个几乎全透明的橘色块」——alpha 被一起替换，没有和底图混合。转回 RGB 就是一块死橘色。

```python
def overlay(img):
    """半透明的东西一律画在独立图层上，再 alpha_composite 回去。"""
    lay = Image.new("RGBA", img.size, (0, 0, 0, 0))
    return lay, ImageDraw.Draw(lay)
```

调色、发光、遮幅、渐变遮罩，全部走这个。别偷懒用 `fill=(0,0,0,120)` 直接画。

### 2. 帧格：抽帧时间必须落在 `n / fps` 上

按秒写时间点时，`19.25 × 30 = 577.5` —— 取整后抽到的是第 577 号帧，也就是 19.233 秒，
比你以为的早了 17ms。拿这一帧和另一版对比，会算出 4% 的假差异，然后你去修一个不存在的问题。

抽帧前先 `round(t * fps) / fps`。所有对比、所有 diff、所有「这一帧变了吗」都要落在帧格上。

### 3. 视差的归属：只有「会动的背景」才有视差

规则：**每一个有具体位置的物件（房子、长椅、树、水面）都在 parallax 1.0 层**，
只有通用重复风景（远山、远处屋顶、云）才用 0.1~0.4。

一旦把长椅放进 0.6 层，人物站在它前面就会随时间慢慢错位——而且只在镜头横移时错，
静止帧看不出来，等发现时已经全片返工。

### 4. 精灵尺度：整数倍放大是免费的「镜头推近」

要一个中景，不需要另画一套大 sprite。**把 sprite 按整数倍 NEAREST 放大再贴**，
得到的就是同一套像素格的中景：

```python
out = sprite.resize((w * scale, h * scale), Image.Resampling.NEAREST)
# 脚点也要跟着乘：ground - 22 * scale，别忘了减
```

本项目长椅镜头用 `scale=2`（26×24 → 52×48），在 256 宽的画布里就是两个人并坐的中景。
**只有 1 倍和 2 倍好看，3 倍开始像素格太大、脸会崩**，要 3 倍以上就重画 sprite。

### 5. 小物件的辨识：形状靠间距，不靠轮廓

三个具体的教训，全部来自「画出来自己也认不出是什么」：

- **实心 = 木箱**。长椅靠背画成一整块板，放大后是一只木箱；改成四根横档、
  档间留 1 逻辑像素缝、透出后面的地面，才认得出是长椅。
  **负空间比正形更能定义物体。**
- **等距排列 = 贴图**。水面波纹等距排，会浮出一层均匀虚线网格；行距必须随深度递增
  （`y += 2 + int(k * 4)`），步长和起始位置也随行号变。
- **单像素点 = 彩纸**。夕阳碎金用「单像素点 + 隔三取一」，放大后像撒开的纸屑；
  改成一段段短横条才聚成反光柱。

另外：**平色区一定要压暗（vignette）**。整张画里唯一没有明暗变化的那块地面，
不压一下会像一块贴上去的板子。

## 七、运动、音效与交互层

- **运动就是函数**。`breathe_at(t)` 是「每 3.2 秒整体抬 1px，停 0.14 秒」；
  `blink_at(t)` 是「每 3.9 秒闭眼 0.13 秒」。这种呼吸和眨眼不要用关键帧，
  一个周期函数就够，而且永远对得齐拍。
- **睡着的人不能眨眼**。`blink_at()` 直接传进去，她躺着还在眨眼，
  配上一个写着「她睡着了」的选项框就穿帮了。状态优先于通用动画。
- **音效全部程序合成**。131 条 `sfx.py`：方波做拾取音、噪声包络做脚步、
  扫频做升级。每一个音的时间点从画面事件反算，误差要求 0——因为音效和画面是同一份数据生成的。
- **交互层的落点先定边界再排版**。见第四节。

## 八、机械验收

代码渲染的最大好处是**每一帧都能被算出来检查**，别浪费：

```bash
# 1) 音画同步：把成片音轨和源 mp3 都解码成 8kHz 包络做互相关
python check_sync.py
# 期望：最佳 lag = 0 点 ; 归一化相关 > 0.99
# lag 不为 0 说明 ffmpeg 有 offset；相关低于 0.95 说明混音改过动态
```
```bash
# 2) 放大无损：检查世界素材层是否保持整数倍纯色像素块
python scripts/pixel_spec.py audit-scale images/world_layer.png --scale 4
```
```bash
# 3) 逐帧密采：抓单帧闪断（本项目在 42 秒窗口里出了 1260 帧）
ffmpeg -i 成片.mp4 -vf "select='between(t,STAT,END)'" -vsync 0 frames/f%04d.png
```
```bash
# 4) 差分抽帧：相邻两帧做像素差，突变点就是闪断/跳变
#    阈值按画面复杂度定，先跑一遍看直方图再定阈值，不要拍一个数
```

自查清单：

- [ ] 每一帧都落在帧格上（没有 577.5 这种时间点）
- [ ] 抽 3 帧放大到 400%，像素格等宽、没有小数坐标造成的缝
- [ ] 所有半透明都在独立图层，没有一整块死色
- [ ] 镜头横移时，人物与长椅/门/桌子的相对位置不变
- [ ] 文字类场景没有被 NEAREST 放大（字边缘是平滑的，不是方块）
- [ ] 封面缩到 320×180，歌名可认、歌手名可辨
- [ ] 音效与画面事件逐条对上（同一份数据生成，不该有偏差）

## 九、最小骨架

`assets/procedural_skeleton/` 是一个两百多行的可跑例子（一半是注释），
把逻辑画布、整数放大、独立 RGBA 图层、中文题字两条路线都演了一遍：

```bash
cd assets/procedural_skeleton && python3 skeleton.py
# out/out_frame.png      1024×576   横版画面 + 矢量题字
# out/out_cover.png      1080×1920  竖版封面，同一套 scene() 换参数
# out/out_text_probe.png 1600×864   像素字 14/20/28px 三档对照，自己看下限
```

要开工，改三处就够：`PAL` 的色阶、`scene()` 里的物件、`H_TITLE` / `V_TITLE` 的排版。
sprite 用字符网格写，场景用矩形和线写，别一上来就写复杂的光照模型——
像素画的质感来自**色阶数量和明暗分区**，不来自渐变。
