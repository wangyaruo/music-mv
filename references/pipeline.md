# 完整流程与数据结构

SKILL.md 讲"做什么"，这里讲"数据怎么流动"和"每一步的判断依据"。

## 数据流

```
song.mp3
   │
   ├─ beat_sync.py ──────────► beats.json          BPM / 拍点 / 网格
   │
   ├─ style_advisor.py ──────► 风格候选（人工选一个）
   │
   ├─ song_structure.py ─────► structure.json      段落参考（不作准）
   │
lyrics.txt（人工核对）
   │
   ├─ groups.json（人工切组）
   │      └─ lyrics_timing.py ─► lines_timing.json  逐句起止
   │
shots.tsv（人工写分镜）
   │
   ├─ build_lines.py ─────────► lines.json          加字幕位置 + 片头尾卡
   │      └─ make_subs.py ────► subs.ass
   │
clips/v01..vNN.mp4
   │
   ├─ build_base.py ──────────► base.mp4            卡拍拼接
   │
   └─ mix_final.py ───────────► 成片.mp4            字幕 + 调色 + 响度
```

三条"人工"环节不能自动化：**风格选择**、**歌词校订**、**分镜表**。
这三件事决定了片子好不好看，剩下的都是工程。

## beats.json

```json
{
  "bpm": 122.21,
  "beat_period": 0.4909,
  "offset": 0.0464,
  "duration": 255.814,
  "beats": [0.0464, 0.5373, ...],
  "subdiv": {"1": 0.4909, "2": 0.2455, "4": 0.1227, "8": 0.0614}
}
```

- `offset` 是第一个拍点的时刻。所有网格都是 `offset + k × 步长`
- `subdiv` 是分拍网格，字幕逐字吸附用 1/8 拍（0.0614s），歌词起止吸附用 1/4 拍

**为什么要吸附**：拍点网格是音乐的时间骨架。字幕每字落在网格上，观众会觉得
"字是踩着音乐出来的"；落在网格之间，同样的时间差也会觉得"有点乱"。

## groups.json

```json
{
  "grid_div": 4,
  "max_shift": 0.10,
  "groups": [
    {"t0": 32.00, "t1": 35.90, "lines": ["第一句"]},
    {"t0": 35.95, "t1": 43.40, "lines": ["第二句", "第三句"]}
  ]
}
```

组的边界来自 ASR 的段落切分。组内按字数比例分配，再吸附到 `beat_period / grid_div`
的网格，位移上限 `max_shift`。

`max_shift` 为什么是 0.10：1/4 拍约 0.12s，位移超过 0.10s 就意味着"跨了将近半拍"，
那还不如不吸附。这是一个经验阈值。

## shots.tsv

| 列 | 说明 |
|---|---|
| `id` | `s01` 起连续编号；素材文件名去掉字母前缀（`s01` → `v01.mp4`） |
| `t0` / `t1` | 秒；`t0` 即切点，会被吸附到拍点 |
| `place` | `T` / `M` / `B`，这一镜字幕该放的位置 |
| `lyric` | 这一镜对应的歌词（可以空，前奏尾奏为空） |
| `scene` | 画面描述，直接用作出图提示词主体 |
| `motion` | 运动描述，直接用作图生视频提示词主体 |

**单镜时长上限**由图生视频能力决定，通常是 6 秒。超过就拆镜。

**`place` 怎么填**：看画面构图，不看歌词内容。

| 构图 | place |
|---|---|
| 人物在画面下半部（站姿、坐姿、大小全景） | `T` |
| 人物在画面中部偏上，下方留白多 | `B` |
| 人物填满画面（特写） | `M` 或 `B`，看哪边能挤出空间 |
| 大空景（天空、水面、远景） | 任意，选和前后镜不同的 |

## lines.json

`build_lines.py` 的产物，`make_subs.py` 的输入。每条：

```json
{
  "start": 126.41, "end": 130.26,
  "text": "琥珀色黄昏像糖 在很美的远方",
  "place": "T",
  "shot": "s24"
}
```

`shot` 是溯源字段，方便查"这句为什么放顶部"。

`place` 的判定用**歌词中点落在哪个镜头**，不用起点。原因：切点吸附到拍点后，
常常比歌词起点晚几十毫秒，按起点会把歌词判给上一个镜头。

## 时间线数学

设切点序列 `b[0..N]`，叠化时长 `D`，第 i 段素材时长 `L[i]`：

```
镜头时长  dur[i]  = b[i+1] - b[i]
所需素材  need[i] = dur[i] + D        （最后一段不需要额外的 D）
慢放倍数  slow[i] = need[i] / L[i]    （only if need > L）
xfade 起始 offset[i] = 累计时长 - D/2
```

`offset = 切点 − D/2` 是核心：叠化跨越切点前后各 `D/2`，
中点在切点上，视觉"切"的瞬间正好压住拍子。

## 案例：周杰伦《园游会》（4:15.58 / 16:9 / 41 镜）

真实数据，可作为复杂度参照。

- BPM 122.21，522 个拍点，1/8 拍网格 0.0614s
- 演唱区间 32.00–204.73s，其余 83 秒是纯器乐（前奏 32s + 尾奏 51s）
- 36 句歌词 → 36 个歌词镜（s04–s41），前奏 3 镜（s01–s03），尾奏复用 8 段
- 全片 49 段，48 个切点，全部落在 1/4 拍网格 ±0.0005s 内
- 字幕 483 个事件（逐字），位置分布 T18 / B15 / M3
- 音画时长 4:15.58，mean −14.9dB，peak −1.2dB

**这首歌暴露过的四个结构性问题，都可以作为通用检查项：**

1. **歌词错字**：「陪我数羊」被记成「被我收得好好的」，「我悄悄出现」被记成
   「我悄悄住进」。记忆会补全，必须多源核对。
2. **第二遍按字数重分配**：导致后半段逐句滞后最多 2.8s。正确做法是
   `第二遍 = 第一遍 + 94.5s`。
3. **切点为压时长被挪动**：7 个镜头的切点比歌词晚 0.37–0.98s，
   表现为"字幕换了、画面还没切"。
4. **单镜主体太小导致画风跑偏**：0:40 那镜退化成写实风景照，
   41 张里唯一一张风格孤岛。

**返工记录**：首版黏土定格被否决，41 张图 + 41 段视频全部重做，成本翻倍。
**结论**：风格必须在出第一张图之前锁定。
